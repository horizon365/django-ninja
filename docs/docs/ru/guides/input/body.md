# Тело запроса

Тело запроса обычно используется в операциях «создания» и «обновления» (POST, PUT, PATCH).
Например, при создании ресурса с помощью POST или PUT тело запроса обычно содержит представление создаваемого ресурса.

Чтобы объявить тело запроса, нужно использовать **`Schema` из Django Ninja**.

!!! note
    «Под капотом» **Django Ninja** использует всю мощь и возможности модели <a href="https://pydantic.com.cn/" class="external-link" target="_blank">Pydantic</a>.
    Псевдоним `Schema` был выбран, чтобы избежать путаницы в коде при работе с моделями Django, поскольку класс модели Pydantic по умолчанию называется `Model`, что конфликтует с классом `Model` в Django.
    

## Импорт Schema

Сначала нужно импортировать `Schema` из `ninja`:

```python hl_lines="2"
{!./src/tutorial/body/code01.py!}
```

## Создание модели данных

Затем объявите свою модель данных как класс, наследующий от `Schema`.

Используйте стандартные типы Python для всех атрибутов:

```python hl_lines="5 6 7 8 9"
{!./src/tutorial/body/code01.py!}
```

Примечание: если вы задаёте значение атрибута по умолчанию равным **`None`**, он становится необязательным в теле запроса. Например, приведённая выше модель объявляет JSON-«`object`» (или Python `dict`) следующего вида:

```JSON
{
    "name": "Katana",
    "description": "An optional description",
    "price": 299.00,
    "quantity": 10
}
```

...поскольку `description` необязателен (его значение по умолчанию — `None`), такой JSON-«`object`» также будет корректным:

```JSON
{
    "name": "Katana",
    "price": 299.00,
    "quantity": 10
}
```

## Объявление в качестве параметра

Чтобы добавить его в вашу *операцию пути*, объявите его так же, как вы объявляете параметры пути и запроса:


```python hl_lines="13"
{!./src/tutorial/body/code01.py!}
```

...и укажите в качестве его типа созданную вами модель `Item`.

## Результат

Используя лишь это объявление типа Python, **Django Ninja** будет:

* Читать тело запроса как JSON.
* Преобразовывать данные к соответствующим типам (при необходимости).
* Проверять данные.
    * Если данные некорректны, будет возвращена понятная и содержательная ошибка, которая точно указывает место и содержание ошибочных данных.
* Предоставлять вам полученные данные в параметре `item`.
    * Поскольку вы объявили его тип как `Item` в функции, вы также получите поддержку редактора (автодополнение и т. д.) для всех атрибутов и их типов.
* Генерировать определения <a href="https://json-schema.org" class="external-link" target="_blank">JSON Schema</a> для вашей модели, которые вы можете использовать в любом месте проекта, где они нужны.
* Эти схемы станут частью сгенерированной схемы OpenAPI и будут использоваться автоматической документацией <abbr title="User Interfaces">UI</abbr>.

## Тело запроса + параметры пути

Вы можете объявлять параметры пути **и** тело запроса одновременно.


**Django Ninja** распознает, что параметры функции, совпадающие с параметрами пути, должны браться **из пути**, а параметры функции, объявленные с `Schema`, должны браться **из тела запроса**.

```python hl_lines="11 12"
{!./src/tutorial/body/code02.py!}
```

## Тело запроса + параметры пути + параметры запроса

Вы также можете одновременно объявлять **тело запроса**, параметры **пути** и **запроса**.

**Django Ninja** распознает каждый параметр и возьмёт данные из правильного места.

```python hl_lines="11 12"
{!./src/tutorial/body/code03.py!}
```

Параметры функции будут распознаны следующим образом:

* Если параметр также объявлен в **пути**, он будет использоваться как параметр пути.

 
* Если параметр является **простым типом** (например, `int`, `float`, `str`, `bool` и т. д.), он будет интерпретирован как параметр **запроса**.
* Если параметр объявлен как тип **Schema** (или Pydantic `BaseModel`), он будет интерпретирован как **тело запроса**.
