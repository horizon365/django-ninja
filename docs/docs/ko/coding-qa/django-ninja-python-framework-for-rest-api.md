Django-Ninja: REST API를 위한 Python 프레임워크
===========================================================



> 최근 REST API로 아주 간단한 CRUD 서비스를 만들고 싶었습니다. 이것저것 찾아본 결과, 두 인기 프레임워크의 장점을 결합한 간단한 프레임워크를 발견했습니다. 그것이 바로 Django-ninja입니다...

* * *


TL;DR
-----


최근 REST API로 아주 간단한 CRUD 서비스를 만들고 싶었습니다. 이것저것 찾아본 결과, 두 인기 프레임워크의 장점을 결합한 간단한 프레임워크를 발견했습니다. 그것이 바로 Django-ninja이며, 저는 이것을 Django와 FastAPI의 결합체로 생각합니다.

---
왜 이것이 유익한 접근 방식이라고 생각하는지 설명해 드리겠습니다.


제 배경을 강조하자면, 저는 Python Django 개발자이며 Flask로 몇 가지 프로젝트를 해본 경험이 있습니다.


FastAPI의 인기에 힘입어 먼저 시도해 보고 싶었습니다. 그래서 문서를 따라 예제를 실행해 봤고, 느낌은, 음, 멋지다는 것이었습니다. 그다음 Pydantic의 사용이 저를 흥분시켰습니다. 가장 중요한 것은 async 기반이라는 점입니다. Swagger UI에서 OpenAPI가 완벽하고 손쉽게 생성되는 것은 더욱 매력적이었습니다.


이것은 제게 눈을 뜨게 해준 경험이었습니다. 그래서 더 깊이 파고들기 시작했습니다.


거기서 저는 FastAPI가 Django처럼 "배터리 포함"이 아니기 때문에 여전히 ORM(SQLAlchemy 또는 SQLModel)을 설정해야 하며, Alembic 같은 데이터베이스 마이그레이션 도구를 위한 별도의 서드파티 패키지도 필요하다는 것을 발견했습니다.


그래서 저는 스스로에게 물었습니다. 설정은 더 적으면서 더 안정적인 더 나은 솔루션이 있지 않을까? 아직 주목받지 못한 무언가가 있을지도 모릅니다. 그리고 검색을 시작했습니다.

그래서 분명히 Django Ninja에 관심을 갖게 되었고, 여기에 제가 좋다고 생각하는 이유가 있습니다.

**인기도**
--------------


Django-Ninja는 가장 인기 있고 널리 알려진 웹 프레임워크인 Django 위에 구축되었습니다. Django-Ninja는 2020년 말에 처음 릴리스되었으며, 불과 약 3년 만에 상당한 인기를 얻었습니다.

**공통 프로젝트 구조**
-----------


Flask 및 FastAPI와 달리 Django는 프로젝트를 생성할 때 구조를 강제합니다. 그러나 프로젝트를 유지 관리하는 방식 측면에서는 더 유연합니다. 이것이 Django의 마음에 드는 점인데, 다른 Django 개발자가 프로젝트를 얼마나 쉽게 따라올 수 있는지를 크게 향상시키기 때문입니다.


네, Django Rest Framework(DRF)도 이것을 할 수 있습니다. 하지만 제가 "빠른 개발"이라고 말했죠? 간단하고 체계적인 코드를 좋아하지 않을 사람이 있을까요? 이것이 Django-Ninja 사용의 아름다움입니다.

**강력한 ORM**
------------


다시 말하지만, 강력한 코어 프레임워크(Django)와 연관되어 있다는 것이 Django-Ninja에 명성을 가져다줍니다.


SQL 쿼리를 덜 안전한 방식으로 직접 작성하는 대신 ORM을 사용하는 경향이 있습니다. ORM은 간단하고 안전한 데이터베이스 호출을 작성하는 데 도움이 됩니다.


그러나 물론 Django ORM과 SQLAlchemy ORM 사이의 개념은 다릅니다. Django ORM은 Active Record 패턴을 사용하고, SQLAlchemy는 Data Mapper 패턴을 사용하는데, 이는 나중에 다른 블로그에서 자세히 설명하겠습니다.

**  
사용하기 쉬운 API 문서
-----------------


네, DRF(Django Rest Framework)에는 자체 API 문서가 있습니다. 하지만 제 생각에 OpenAPI Swagger UI가 훨씬 낫습니다. 그래서 DRF와 함께 Swagger UI가 필요했을 때 drf-yasg라는 swagger 생성기 패키지를 사용했는데, 꽤 좋은 결과를 얻었습니다.


하지만 FastAPI처럼 Django-Ninja에서는 url 함수 외에 추가 코드를 작성하지 않고도 대화형 OpenAPI Swagger UI를 얻을 수 있습니다.

**성능**
---------------


FastAPI와 마찬가지로 Pydantic을 통한 내장 타입 강제 지원과 비동기 실행을 갖추고 있습니다.


Django-ninja 문서는 Flask, DRF, Django-ninja 간의 벤치마크 데이터를 비교하며 이를 자랑하는 것도 잊지 않았습니다.

**더 빠른 배포**
-------------------


다시 말하지만, FastAPI처럼 매우 적은 코드 베이스로 REST API 서비스를 가동할 수 있습니다. 동시에 적합하다고 생각하는 어떤 철학적 접근 방식으로도 쉽게 개발할 수 있도록 도와줍니다. 이것이 특권의 아름다움입니다.


최소한의 간결한 코드 베이스는 높은 가독성으로 이어집니다. 이는 다시 더 빠른 구현을 위한 직관을 촉진합니다.
