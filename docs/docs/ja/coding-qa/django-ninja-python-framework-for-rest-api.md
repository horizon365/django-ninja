TL;DR
-----


最近、REST API で非常にシンプルな CRUD サービスを構築したいと思っていました。いろいろ探した結果、2 つの人気フレームワークの長所を組み合わせたシンプルなフレームワークを見つけました。それが Django-ninja です。私はこれを Django と FastAPI の組み合わせだと考えています。

---
なぜこれが有益なアプローチだと考えるのか、説明させてください。


私のバックグラウンドを強調しておくと、私は Python Django 開発者であり、Flask でもいくつかのプロジェクトを行ったことがあります。


FastAPI の人気が高まる中、まずはそれを試してみたいと思いました。そこでドキュメントに従ってサンプルを実行してみたところ、感想は「うん、これはクールだ」というものでした。そして Pydantic の使用にワクワクしました。何より重要なのは、それが async の上に構築されていることです。Swagger UI 上で完璧かつ手間なしに OpenAPI が生成される点が、さらに魅力的でした。


これは私にとって目を開かれる経験でした。そこで、私はさらに深く掘り下げ始めました。


そこで気づいたのは、FastAPI は Django のように「batteries-included（電池付き）」ではないため、ORM（SQLAlchemy や SQLModel）の設定がまだ必要であり、Alembic のようなデータベースマイグレーションツールのために別のサードパーティパッケージが必要になることは言うまでもない、ということでした。


そこで、もっと設定が少なく、より安定したより良い解決策がどこかにないかと考えました。まだ注目されていない何かがあるかもしれません。そして探し始めました。


選択肢のいくつかをリストアップしました（GitHub のスター数は 2023 年 9 月時点）：


Flask: 64K stars — 初回リリース：2010 年 4 月 1 日


FastAPI: 61.8K stars — 初回リリース：2018 年 12 月 5 日


Django Rest Framework: 26.2K stars — 初回リリース：2005 年 7 月 21 日

Django Ninja: 4.8K stars — 初回リリース：2020 年 12 月 20 日


というわけで、明らかに私は Django Ninja に興味を持つようになりました。以下は、それが良いと考える理由です。

**人気**
--------------


Django-Ninja は、最も人気のある言うなれば標準的な web フレームワークである Django の上に構築されています。Django-Ninja は 2020 年末に初めてリリースされ、わずか 3 年ほどで大きな人気を得ました。

**共通のプロジェクト構造**
-----------


Flask や FastAPI とは異なり、Django はプロジェクトを作成する際に構造を強制します。しかし、プロジェクトをどう管理したいかという点ではより柔軟です。これは私が Django について気に入っている点です。他の Django 開発者がプロジェクトを追いかけやすさが大幅に向上するからです。


そうはいっても、Django Rest Framework（DRF）にも同じことが言えます。でも、私が「迅速な開発」と言いましたよね？シンプルで整理されたコードを好まない人がいるでしょうか？それこそが Django-Ninja を使う魅力です。

**強力な ORM**
------------


繰り返しになりますが、強力なコアフレームワーク（Django）と結びついていることも、Django-Ninja の信頼性につながっています。


セキュリティの観点からあまり安全とは言えない方法で自分で SQL クエリを書くのではなく、私たちは ORM を使う傾向にあります。ORM はシンプルで安全なデータベース呼び出しを書く助けになります。


しかしもちろん、Django ORM と SQLAlchemy ORM の概念は異なります。Django ORM は Active Record パターンを使用し、SQLAlchemy は Data Mapper パターンを使用します。これについては後日別のブログで詳しく説明する予定です。

**  
使いやすい API ドキュメント
-----------------


そうです、DRF（Django Rest Framework）には独自の API ドキュメントがあります。しかし私の意見では、OpenAPI の Swagger UI の方がはるかに優れています。そのため、DRF で Swagger UI が必要になったときは、drf-yasg という swagger ジェネレーターパッケージを使いましたが、これはかなり良い仕事をしてくれました。


しかし FastAPI と同様に、Django-Ninja では url 関数以外に追加のコードを一切書かずに、インタラクティブな OpenAPI Swagger UI を得ることができます。

**パフォーマンス**
---------------


FastAPI と同様に、Pydantic による組み込みの型強制サポートと非同期実行を備えています。


Django-ninja のドキュメントも、Flask、DRF、Django-ninja 間のベンチマークデータを比較して、この点を自慢することを忘れていませんでした。

**より速いデリバリー**
-------------------


これも FastAPI と同様に、非常に少ないコードベースで REST API サービスを立ち上げることができます。同時に、自分が適切だと考えるどんな思想的アプローチに従っても、容易に開発を進めることができます。これぞ特権の美しさです。


ミニマルで簡潔なコードベースは高い可読性につながります。これはひいては、より速く実装するための直感を刺激します。
